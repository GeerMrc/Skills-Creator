## 一、文档更新规范

### 条理清晰的迭代式更新

```
第一批更新（必需章节）: 项目概述、快速开始、核心功能
第二批更新（详细说明）: API 文档、配置说明、故障排除
第三批更新（补充内容）: 高级用法、最佳实践、FAQ
```

### 推进项目进度追踪

- 每个文档更新都服务于项目目标
- 更新前确认目标达成
- 更新后验证目标完成

### 文档一致性检查

```bash
# 检查交叉引用链接
grep -r "\[.*\](references/)" . --include="*.md"

# 检查过时引用
grep -r "v0.0.1" . --include="*.md"
```

## 四、文档更新流程

### 场景5: 文档更新（三步法）

```
步骤1: 创建文档分支
└─ git checkout -b docs/update-documentation

步骤2: 更新文档
├─ 编辑文档内容
├─ 检查交叉引用
└─ 更新版本标记

步骤3: 提交合并
├─ git commit -m "docs: update XXX documentation"
├─ git push
└─ 创建PR或直接合并
```

## 六、交叉引用规范

### 链接格式

```markdown
<!-- 相对链接 -->
[链接文本](path/to/file.md)

<!-- 带章节的链接 -->
[链接文本](path/to/file.md#section-id)

<!-- 外部链接 -->
[链接文本](https://example.com)
```

### 引用检查

```bash
# 检查所有 Markdown 链接
grep -r "\[.*\](.*\.md)" . --include="*.md"

# 检查断开的链接（需要工具）
markdown-link-check ./*.md
```

## 八、常见问题

### 问题1: 文档过长

**症状**: 文档超过400行

**解决方案**:
- 拆分为多个专题文档
- 移出详细示例到 examples/
- 使用引用文档结构

### 问题2: 交叉引用失效

**症状**: 链接点击无效

**解决方案**:
- 检查文件路径是否正确
- 检查文件名是否匹配
- 使用相对链接而非绝对链接

### 问题3: 文档内容不一致

**症状**: 同一内容在不同文档中描述不同

**解决方案**:
- 确定单一真实来源
- 其他文档引用而非复制
- 定期审查文档一致性
