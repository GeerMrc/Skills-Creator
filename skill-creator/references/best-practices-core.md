# Agent-Skills 最佳实践 - 核心原则

## 概述

本文档涵盖 Agent-Skills 开发的核心原则，包括渐进式披露架构、描述写作规范和组织原则。

> **继续阅读**: [高级技巧](best-practices-advanced.md) 包含 Token 优化、脚本黑盒化实践和常见反模式。

## 渐进式披露三层架构

### 架构图

```
┌─────────────────────────────────────────────────┐
│ 第一层：YAML Frontmatter (~100词)               │
│ - name + description                            │
│ - 让 Claude 判断是否激活技能                    │
├─────────────────────────────────────────────────┤
│ 第二层：SKILL.md 入口点 (≤150行推荐)            │
│ - 技能概览、核心能力、快速开始                  │
│ - 导航到详细文档                                │
├─────────────────────────────────────────────────┤
│ 第三层：引用文件 (每个200-300行)                │
│ - 详细文档、模式、示例                          │
│ - 按需加载，避免污染上下文                      │
└─────────────────────────────────────────────────┘
```

### 第一层：YAML Frontmatter

**目的**：让 Claude 快速判断是否激活技能

**内容**：
```yaml
---
name: skill-name
description: |
  功能陈述（1句话）。

  何时使用：
  - 场景1
  - 场景2

  触发词：关键词1、关键词2、关键词3
---
```

**大小建议**：100-200词

**关键要素**：
- **功能陈述**：技能做什么，使用第三人称
- **使用场景**：何时使用此技能（2-4项）
- **触发词**：什么情况下激活（3-6个关键词）

### 第二层：SKILL.md 入口点

**目的**：提供技能概览和导航

**大小限制**：
- 推荐：≤150行
- 最大：≤500行

**必需章节**：
```markdown
## 技能概述
## 核心能力
## 快速开始
## 工作流程
## 详细文档（导航到引用文件）
```

**内容建议**：
- 概述：2-3段，说明技能定位和价值
- 核心能力：6-8项，使用动词开头的短语
- 快速开始：2-3个常见场景示例
- 工作流程：简化的流程图或步骤列表
- 导航：引用文件的链接和简要说明

### 第三层：引用文件

**目的**：提供深度内容，按需加载

**大小建议**：每个文件200-300行

**命名规范**：
- `mcp-tools-reference.md` - MCP 集成指南
- `best-practices-core.md` - 最佳实践（核心原则）
- `best-practices-advanced.md` - 最佳实践（高级技巧）
- `validation.md` - 验证规范
- `examples.md` - 使用示例
- `api-reference.md` - API 文档

**组织原则**：
- 每个文件专注单一主题
- 文件之间避免相互引用
- 从 SKILL.md 直接链接

## 描述写作规范

### 第三人称原则

**正确示例**：
```yaml
description: |
  Docker 容器管理能力。创建、启动、停止、删除容器。
```

**错误示例**：
```yaml
# ❌ 第一人称
description: "我可以帮助您管理容器..."

# ❌ 第二人称
description: "使用这个工具来管理容器..."

# ❌ 不确定性
description: "这是一个容器管理工具..."
```

### 三要素法则

**1. 功能陈述**（必须）
- 技能做什么
- 使用能力描述，非工具描述
- 1句话，约20字符

**2. 使用场景**（必须）
- 何时使用此技能
- 2-4个具体场景
- 每个场景1行

**3. 触发词**（必须）
- 什么情况下激活
- 3-6个关键词
- 用户可能使用的词汇

**完整示例**：
```yaml
---
name: pdf-processor
description: |
  PDF 文档处理能力。提取文本、填充表单、合并文档、添加水印。

  何时使用：
  - 需要从 PDF 提取文本或图片
  - 填充 PDF 表单模板
  - 合并多个 PDF 文件
  - 为 PDF 添加水印或签名

  触发词：PDF、提取、表单、合并、水印、文档
---
```

### 长度建议

| 指标 | 最小 | 推荐 | 最大 |
|------|------|------|------|
| 字符数 | 50 | 150-300 | 1024 |
| 词汇数 | 10 | 50-100 | 200 |

## 按能力组织原则

### 能力 vs 工具

**按工具组织**（不推荐）：
```
- docker-skill    # Docker 工具
- kubectl-skill   # kubectl 工具
- aws-skill       # AWS 工具
```

**按能力组织**（推荐）：
```
- container-management    # 容器管理能力（包含 docker + kubectl）
- cloud-deployment        # 云部署能力（包含 AWS + Azure + GCP）
- infrastructure-as-code  # 基础设施代码能力
```

### 能力命名

**推荐格式**：
- **动名词形式**：`processing-pdfs`、`analyzing-data`、`managing-containers`
- **名词短语**：`pdf-processing`、`data-analysis`、`container-management`

**避免使用**：
- `helper` - 太模糊
- `utils` - 太通用
- `tools` - 按工具组织
- `manager` - 除非真正管理资源

### 示例对比

| 不推荐 | 推荐 | 原因 |
|--------|------|------|
| `git-helper` | `git-workflow` | workflow 比 helper 更具体 |
| `docker-tools` | `container-management` | 按能力而非工具命名 |
| `file-utils` | `file-operations` | operations 比 utils 更明确 |
