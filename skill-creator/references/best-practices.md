## 概述

开发高质量 Agent-Skills 需要遵循一套经过验证的最佳实践。本文档涵盖渐进式披露架构、描述写作规范、组织原则等核心实践。

## 渐进式披露三层架构

### 架构图

```
┌─────────────────────────────────────────────────┐
│ 第一层：YAML Frontmatter (~100词)               │
│ - name + description                            │
│ - 让 Claude 判断是否激活技能                    │
├─────────────────────────────────────────────────┤
│ 第二层：SKILL.md 入口点 (≤150行推荐)            │
│ - 技能概览、核心能力、快速开始                  │
│ - 导航到详细文档                                │
├─────────────────────────────────────────────────┤
│ 第三层：引用文件 (每个200-300行)                │
│ - 详细文档、模式、示例                          │
│ - 按需加载，避免污染上下文                      │
└─────────────────────────────────────────────────┘
```

### 第一层：YAML Frontmatter

**目的**：让 Claude 快速判断是否激活技能

**内容**：
```yaml
---
name: skill-name
description: |
  功能陈述（1句话）。

  何时使用：
  - 场景1
  - 场景2

  触发词：关键词1、关键词2、关键词3
---
```

**大小建议**：100-200词

**关键要素**：
- **功能陈述**：技能做什么，使用第三人称
- **使用场景**：何时使用此技能（2-4项）
- **触发词**：什么情况下激活（3-6个关键词）

### 第二层：SKILL.md 入口点

**目的**：提供技能概览和导航

**大小限制**：
- 推荐：≤150行
- 最大：≤500行

**必需章节**：
```markdown
## 技能概述
## 核心能力
## 快速开始
## 工作流程
## 详细文档（导航到引用文件）
```

**内容建议**：
- 概述：2-3段，说明技能定位和价值
- 核心能力：6-8项，使用动词开头的短语
- 快速开始：2-3个常见场景示例
- 工作流程：简化的流程图或步骤列表
- 导航：引用文件的链接和简要说明

### 第三层：引用文件

**目的**：提供深度内容，按需加载

**大小建议**：每个文件200-300行

**命名规范**：
- `mcp-integration.md` - MCP 集成指南
- `best-practices.md` - 最佳实践
- `validation.md` - 验证规范
- `examples.md` - 使用示例
- `api-reference.md` - API 文档

**组织原则**：
- 每个文件专注单一主题
- 文件之间避免相互引用
- 从 SKILL.md 直接链接

## 描述写作规范

### 第三人称原则

**正确示例**：
```yaml
description: |
  Docker 容器管理能力。创建、启动、停止、删除容器。
```

**错误示例**：
```yaml
# ❌ 第一人称
description: "我可以帮助您管理容器..."

# ❌ 第二人称
description: "使用这个工具来管理容器..."

# ❌ 不确定性
description: "这是一个容器管理工具..."
```

### 三要素法则

**1. 功能陈述**（必须）
- 技能做什么
- 使用能力描述，非工具描述
- 1句话，约20字符

**2. 使用场景**（必须）
- 何时使用此技能
- 2-4个具体场景
- 每个场景1行

**3. 触发词**（必须）
- 什么情况下激活
- 3-6个关键词
- 用户可能使用的词汇

**完整示例**：
```yaml
---
name: pdf-processor
description: |
  PDF 文档处理能力。提取文本、填充表单、合并文档、添加水印。

  何时使用：
  - 需要从 PDF 提取文本或图片
  - 填充 PDF 表单模板
  - 合并多个 PDF 文件
  - 为 PDF 添加水印或签名

  触发词：PDF、提取、表单、合并、水印、文档
---
```

### 长度建议

| 指标 | 最小 | 推荐 | 最大 |
|------|------|------|------|
| 字符数 | 50 | 150-300 | 1024 |
| 词汇数 | 10 | 50-100 | 200 |

## 按能力组织原则

### 能力 vs 工具

**按工具组织**（不推荐）：
```
- docker-skill    # Docker 工具
- kubectl-skill   # kubectl 工具
- aws-skill       # AWS 工具
```

**按能力组织**（推荐）：
```
- container-management    # 容器管理能力（包含 docker + kubectl）
- cloud-deployment        # 云部署能力（包含 AWS + Azure + GCP）
- infrastructure-as-code  # 基础设施代码能力
```

### 能力命名

**推荐格式**：
- **动名词形式**：`processing-pdfs`、`analyzing-data`、`managing-containers`
- **名词短语**：`pdf-processing`、`data-analysis`、`container-management`

**避免使用**：
- `helper` - 太模糊
- `utils` - 太通用
- `tools` - 按工具组织
- `manager` - 除非真正管理资源

### 示例对比

| 不推荐 | 推荐 | 原因 |
|--------|------|------|
| `git-helper` | `git-workflow` | workflow 比 helper 更具体 |
| `docker-tools` | `container-management` | 按能力而非工具命名 |
| `file-utils` | `file-operations` | operations 比 utils 更明确 |

## Token 优化技巧

### 1. 保持 SKILL.md 简洁

**移除内容**：
- 详细示例 → 移至 `examples/`
- API 文档 → 移至 `references/api.md`
- 配置说明 → 移至 `references/config.md`
- 历史背景 → 完全删除

**保留内容**：
- 技能概述（2-3段）
- 核心能力列表
- 快速开始（2-3个简单示例）
- 导航到引用文件

### 2. 使用引用文件

**好处**：
- 减少首次加载 Token
- 按需加载详细内容
- 便于维护和更新

**实践**：
```
SKILL.md (100行)
├── references/
│   ├── mcp-integration.md (200行)  # 需要时加载
│   ├── best-practices.md (250行)   # 需要时加载
│   └── validation.md (220行)       # 需要时加载
```

### 3. 避免内容重复

**错误示例**：
```markdown
## 核心能力

### 文件处理
处理各种文件格式...

## 详细说明

### 文件处理
详细说明如何处理文件...（重复内容）
```

**正确示例**：
```markdown
## 核心能力

1. 技能验证 - 验证技能规范符合度

## 详细文档

- **[验证规范详解](validation.md)**
```

### 4. 控制引用深度

**错误**（深度嵌套）：
```
SKILL.md → advanced.md → internal.md → utils.md → details.md
```

**正确**（扁平引用）：
```
SKILL.md → advanced.md
SKILL.md → internal.md
SKILL.md → utils.md
```

**规则**：引用深度 ≤2层

## 脚本黑盒化实践

### 原则

脚本作为独立命令调用，不读取源码到上下文。

### 好处

1. **Token 高效**：不加载脚本源码
2. **执行可靠**：预测试的脚本行为一致
3. **维护简单**：脚本独立修改不影响技能

### 实现方式

**1. 提供 --help**

```python
#!/usr/bin/env python3
import argparse

def main():
    parser = argparse.ArgumentParser(description='验证 Agent-Skill 规范')
    parser.add_argument('path', help='技能目录路径')
    parser.add_argument('--template', help='模板类型')
    args = parser.parse_args()
    # ...

if __name__ == '__main__':
    main()
```

**2. 在 SKILL.md 中指引使用**

在 SKILL.md 中添加脚本使用说明：

```markdown
## 运行验证

\`\`\`bash
# 查看帮助
python scripts/validate.py --help

# 验证技能
python scripts/validate.py /path/to/skill
\`\`\`
```

注意：先运行 `--help` 了解用法，而非读取源码。

**3. 错误处理和提示**

```python
try:
    validate_skill(args.path)
except FileNotFoundError:
    print(f"错误：技能路径不存在: {args.path}")
    sys.exit(1)
except Exception as e:
    print(f"错误：{e}")
    sys.exit(1)
```

## 常见反模式

### 1. 文档思维

**症状**：把技能当作通用文档

**表现**：
- SKILL.md 超过500行
- 包含大量教程内容
- 详尽的历史背景和设计理念

**解决方案**：
- 移动详细内容到引用文件
- 保留概览和快速导航
- 删除非核心信息

### 2. 上下文爆炸

**症状**：激活时加载过多无关内容

**表现**：
- 首次加载超过5000 tokens
- 90%内容与当前任务无关
- 包含所有可能的边缘情况

**解决方案**：
- 实施渐进式披露
- 精简 SKILL.md
- 使用引用文件按需加载

### 3. 工具堆砌

**症状**：按工具而非能力组织

**表现**：
- 每个工具一个技能
- 技能名称直接使用工具名
- 没有工作流编排

**解决方案**：
- 按工作流能力分组
- 合并相关工具技能
- 在技能内编排工具使用

## 评分标准

| 评分 | 渐进式披露 | 描述质量 | 能力组织 |
|------|-----------|---------|---------|
| 优秀 (90-100) | ≤150行，三层清晰 | 三要素完整，第三人称 | 按能力，名称明确 |
| 良好 (75-89) | ≤200行，有引用 | 功能+场景 | 基本按能力 |
| 及格 (60-74) | ≤350行，引用少 | 有功能描述 | 部分按能力 |
| 不及格 (<60) | >500行 | 缺少要素 | 按工具堆砌 |

## 检查清单

创建技能后，逐项检查：

**结构检查**：
- [ ] SKILL.md ≤ 150行
- [ ] 引用文件 200-300行
- [ ] 引用深度 ≤2层
- [ ] 无重复内容

**描述检查**：
- [ ] 包含功能陈述
- [ ] 包含使用场景
- [ ] 包含触发词
- [ ] 使用第三人称

**组织检查**：
- [ ] 按能力而非工具组织
- [ ] 能力命名明确
- [ ] 脚本有 --help
- [ ] 无深层嵌套
