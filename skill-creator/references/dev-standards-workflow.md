# 九步法开发工作流

> **版本**: v1.0
> **更新日期**: 2026-01-26
> **配套文档**: `dev-standards.md`

---

## 一、九步法总览

```
步骤0: 前置任务审核  → 检查前置任务、确认Git环境
步骤1: 制定开发计划  → .claude/plans/feat-xxx.md
步骤2: 拆分任务清单  → TaskCreate 工具 (3-10个任务)
步骤3: 执行开发工作  → 编码 + 测试
步骤4: 测试验证      → pytest --cov
步骤5: 交叉验证      → 对照计划检查 (支持回退)
步骤6: 更新文档      → CHANGELOG.md
步骤7: 阶段性审计    → 内部审查
步骤8: Git提交       → 版本控制
步骤9: 阶段性汇报    → 生成汇报并归档计划
```

---

## 二、步骤详解

### 步骤0: 前置任务审核

**目的**: 确保基础环境正确

**检查项**:
- ✅ 前一阶段计划已完成
- ✅ 文档已归档到 `archive/`
- ✅ 当前分支为 `develop`
- ✅ 代码已同步

**输出**: 审核报告

---

### 步骤1: 制定开发计划

**目的**: 明确目标、范围和验收标准

**操作**:
```bash
# 在 plans/ 创建计划文档
vim .claude/plans/feat-xxx.md
```

**计划模板**:
```markdown
# 功能名称计划

## 目标
明确的功能目标

## 范围
- 包含: 具体功能列表
- 不包含: 明确排除项

## 验收标准
- [ ] 功能正常工作
- [ ] 测试覆盖率 ≥95%
- [ ] 文档已更新

## 技术依赖
- 依赖项1
- 依赖项2

## 风险
- 风险1 + 缓解措施
- 风险2 + 缓解措施
```

**输出**: 计划文档

---

### 步骤2: 拆分任务清单

**目的**: 将计划分解为可执行的任务

**操作**:
```python
TaskCreate(
    subject="任务名称",
    description="详细描述",
    activeForm="执行中状态描述"
)
```

**任务限制**:
- 3-10个任务
- 使用稳定ID (YYYYMMDD-序号)
- 标注优先级 (P0-P3)

**输出**: 任务清单

---

### 步骤3: 执行开发工作

**目的**: 按优先级顺序执行任务

**操作**:
1. 选择pending状态的任务
2. 标记为in_progress
3. 执行编码 + 测试
4. 遇到阻塞及时记录

**TODO管理**:
- 每完成一步立即更新状态
- 遇到阻塞及时记录
- 定期回顾进度

**输出**: 可运行代码

---

### 步骤4: 测试验证

**目的**: 确保代码质量

**操作**:
```bash
# 编写/更新测试用例
# 运行测试套件
uv run pytest --cov

# 运行质量检查
uv run ruff check .
uv run mypy src/
```

**验收标准**:
- ✅ 测试覆盖率 ≥95%
- ✅ Ruff 0错误
- ✅ Mypy 0错误

**输出**: 测试报告

---

### 步骤5: 交叉验证

**目的**: 对照计划检查完成度

**操作**:
1. 对照计划检查完成度
2. 验证所有验收标准
3. 检查TODO状态一致性
4. 发现问题可回退状态

**TODO回退机制**:
```python
# 回退到执行中
TaskUpdate(taskId="xxx", status="in_progress")

# 完成后更新
TaskUpdate(taskId="xxx", status="completed")
```

**输出**: 验证报告

---

### 步骤6: 更新文档

**目的**: 同步文档与代码

**操作**:
1. 更新技术文档
2. 更新 CHANGELOG.md
3. 更新任务追踪文档
4. 检查交叉引用链接

**文档检查清单**:
- [ ] 内容准确
- [ ] 格式规范
- [ ] 代码示例可运行
- [ ] 交叉引用有效

**输出**: 更新的文档

---

### 步骤7: 阶段性审计

**目的**: 内部审查完成度

**审计内容**:
- ✅ 100%按计划执行
- ✅ 记录偏差和改进措施
- ✅ 代码质量检查通过
- ✅ 准备Git提交信息

**输出**: 审计报告

---

### 步骤8: Git提交

**目的**: 版本控制

**操作**:
```bash
# 提交变更
git add .
git commit -m "feat(scope): description"

# 推送到远程
git push -u origin feature/xxx
```

**Commit规范**:
```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type类型**:
- `feat`: 新功能
- `fix`: Bug修复
- `docs`: 文档更新
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建/辅助工具

**输出**: Git提交记录

---

### 步骤9: 阶段性汇报

**目的**: 总结成果并归档

**操作**:
1. 汇总已完成任务
2. 记录问题和解决方案
3. 记录测试和质量指标
4. 归档计划到 `archive/`

**汇报模板**:
```markdown
# 阶段报告

## 完成任务
- 任务1 ✅
- 任务2 ✅

## 遇到的问题
- 问题1 → 解决方案

## 质量指标
- 测试覆盖率: 96%
- 代码检查: 通过

## 下一阶段
- 计划1
- 计划2
```

**输出**: 汇报文档 + 归档计划

## 三、常见场景流程

### 场景1: 新功能开发 (十步法)

```
步骤0: 前置审核 → 步骤3: 创建功能分支 → 步骤10: 归档计划
```

### 场景2: Bug修复 (五步法)

```
步骤1: 创建修复分支 → 步骤5: 提交合并
```

### 场景3: 代码重构 (六步法)

```
步骤1: 创建重构分支 → 步骤6: 提交合并
```

### 场景4: 文档更新 (三步法)

```
步骤1: 创建文档分支 → 步骤3: 提交合并
```

## 四、TODO管理规范

**状态管理**:
- `pending`: 待执行
- `in_progress`: 执行中（同时只能有一个）
- `completed`: 已完成

**状态流转**:
```
pending → in_progress → completed
  ↑                           ↓
  └──── 未完成/不规范 ────────┘
        (回退到 pending 或 in_progress)
```

**实时更新原则**:
- 每完成一步立即更新状态
- 遇到阻塞及时记录
- 定期回顾进度
- 发现问题及时回退状态

---

## 五、违规处理

| 违规步骤 | 违规行为 | 后果 | 恢复措施 |
|----------|----------|------|----------|
| 步骤0 | 未检查前置任务 | 基础不牢固 | 返回步骤0 |
| 步骤2 | TODO超过10个 | 执行准确性下降 | 拆分为多个小计划 |
| 步骤3 | 未实时更新TODO | 进度不透明 | 补充更新TODO状态 |
| 步骤4 | 跳过测试 | 质量风险 | 补全测试 |
| 步骤5 | 未执行交叉验证 | 遗漏问题 | 执行完整交叉验证 |
| 步骤5 | 发现问题未回退 | 质量缺陷 | 使用TODO回退机制 |
| 步骤6 | 文档未同步 | 技术债务 | 补充文档更新 |
| 步骤7 | 未通过审计 | 进度偏差 | 修正偏差后重新审计 |
| 步骤8 | 提交不规范 | 版本混乱 | 修正提交信息 |
| 步骤9 | 未归档计划 | 计划丢失 | 归档到正确位置 |
