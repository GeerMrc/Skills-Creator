## 性能优化建议

### 1. 预热缓存

应用启动时预加载常用数据到缓存，减少首次请求延迟。

**预热策略**:
- **主动预热**: 应用启动时预加载
- **被动预热**: 首次访问时缓存
- **定时预热**: 后台任务定期刷新热点数据

详见: [缓存高级示例 - 预热缓存](../examples/cache-advanced-examples.md#预热缓存)

### 2. 批量操作优化

在批量验证时启用特殊缓存标记，避免重复计算。设置批量操作标记后，相关函数会优先使用缓存结果。

### 3. 缓存失效策略

数据更新时主动失效相关缓存，保持一致性：
- 使用模式匹配删除相关缓存
- 失效后预热新数据

### 4. 缓存预热时机

根据使用模式选择合适的预热时机：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 主动预热 | 应用启动时预加载 | 常用配置、模板 |
| 被动预热 | 首次访问时缓存 | 偶尔访问的数据 |
| 定时预热 | 后台任务定期刷新 | 热点数据 |

## 缓存相关配置

### 环境变量

通过环境变量调整缓存行为：

```bash
# 缓存大小（默认256）
export SKILL_CREATOR_CACHE_SIZE=512

# 缓存 TTL（默认300秒）
export SKILL_CREATOR_CACHE_TTL=600

# 启用缓存统计（默认启用）
export SKILL_CREATOR_CACHE_STATS=true
```

### Python 配置

根据场景选择合适的配置：

| 配置类型 | max_size | default_ttl | 适用场景 |
|----------|----------|-------------|----------|
| 高性能配置 | 1024 | 600秒 | 高并发场景 |
| 低内存配置 | 128 | 120秒 | 内存受限环境 |
| 实时数据配置 | 256 | 0（不过期） | 需要实时数据的场景 |

详见: [缓存高级示例 - Python配置](../examples/cache-advanced-examples.md#python-配置示例)

### 动态调整缓存

根据命中率动态调整缓存大小：
- 命中率 < 60%: 增大缓存
- 命中率 > 95% 且利用率低: 减小缓存

## 故障排查

### 问题1: 缓存未生效

**症状**: 函数每次都执行，没有从缓存返回

**常见原因**:
- 函数参数包含不可哈希类型（如 dict、list）
- 每次调用使用了不同的参数
- TTL 设置过短，缓存已过期

**排查步骤**:
1. 检查缓存是否创建: `cache.get_stats()`
2. 检查键是否正确: 使用 `cache_key()` 生成键
3. 检查缓存是否存在: `cache.exists(key)`
4. 检查装饰器参数: 确保 TTL 正确

详见: [缓存高级示例 - 故障排查代码](../examples/cache-advanced-examples.md#故障排查代码)

### 问题2: 内存占用过高

**症状**: 应用内存占用持续增长

**解决方案**:
1. 缓存元数据而非完整数据
2. 使用弱引用缓存大对象
3. 定期清理缓存

### 问题3: 缓存命中率低

**症状**: 命中率 < 70%

**优化建议**:
- 增大缓存大小
- 延长 TTL
- 检查缓存键是否稳定

## 缓存监控

### 实时监控

定期检查缓存状态，包括：
- 缓存大小和利用率
- 命中率和命中次数
- 未命中次数

### Prometheus 集成

导出缓存指标到 Prometheus：
- `cache_size`: 当前缓存大小
- `cache_hits`: 缓存命中次数
- `cache_misses`: 缓存未命中次数

详见: [缓存高级示例 - 缓存监控](../examples/cache-advanced-examples.md#缓存监控)

## 高级技巧

### 多级缓存

L1 内存缓存 + L2 磁盘缓存的组合策略：
- L1: 快速访问，容量小
- L2: 较慢访问，容量大
- 回填机制: L2命中后回填L1

### 缓存分区

按类型分区缓存，避免相互影响：
- templates: 模板缓存
- validations: 验证结果缓存
- metadata: 元数据缓存

详见: [缓存高级示例 - 高级技巧](../examples/cache-advanced-examples.md#高级技巧)
