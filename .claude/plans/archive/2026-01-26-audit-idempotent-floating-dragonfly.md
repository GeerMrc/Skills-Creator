## 三、开发规范要求概述

基于CLAUDE.md，以下是开发流程的核心规范：

### 3.1 九步法流程

```
步骤0: 前置任务审核  → 检查前置任务、确认Git环境
步骤1: 制定开发计划  → .claude/plans/feat-xxx.md
步骤2: 拆分任务清单  → Task工具创建任务 (3-10个)
步骤3: 执行开发工作  → 编码 + 测试
步骤4: 测试验证      → pytest --cov (必须新增测试)
步骤5: 交叉验证      → 对照计划检查 (支持回退)
步骤6: 更新文档      → CHANGELOG.md
步骤7: 阶段性审计    → 内部审查 (必须真实)
步骤8: Git提交       → 版本控制
步骤9: 阶段性汇报    → 生成汇报并归档计划
```

### 3.2 TODO管理规范

**任务状态管理**:
- `pending`: 待执行
- `in_progress`: 执行中（同时只能有一个）
- `completed`: 已完成

**状态流转**:
```
pending → in_progress → completed
  ↑                           ↓
  └──── 未完成/不规范 ────────┘
        (回退到 pending 或 in_progress)
```

**实时更新原则**:
- 每完成一步立即更新状态
- 遇到阻塞及时记录
- 定期回顾进度
- 发现问题及时回退状态

### 3.3 质量标准

| 指标 | 要求 | 目标 |
|------|------|------|
| 测试覆盖率 | ≥80% | ≥95% |
| 代码检查 | 0 错误 | 0 警告 |
| 类型检查 | 0 错误 | 完整注解 |
