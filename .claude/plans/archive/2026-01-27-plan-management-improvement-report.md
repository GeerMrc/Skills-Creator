# 计划管理流程规范化改进报告

**报告日期**: 2026-01-27
**报告类型**: 流程规范改进报告
**改进版本**: v1.5
**适用范围**: Skills-Creator 项目计划管理

---

## 一、问题分析

### 1.1 当前问题

在实际项目开发过程中，发现以下不规范现象：

1. **提前归档**: 计划中包含P0/P1/P2/P3任务，但只执行了P1或P1+P2就直接归档
2. **状态不透明**: 未完成的任务没有明确的进度追踪机制
3. **追溯困难**: 阶段性工作缺少commit记录，无法追溯具体做了什么
4. **边界模糊**: 何时可以归档、何时不可以归档，规范不明确

### 1.2 问题影响

- **进度不可控**: 无法准确了解计划实际完成度
- **追溯困难**: 无法通过Git历史或计划文档了解阶段性工作
- **质量风险**: 未完成的任务可能被遗漏
- **协作低效**: 其他开发者无法快速了解计划状态

## 二、改进方案

### 2.1 计划状态管理规范

#### 扩展状态定义（5种）

**旧规范**（4种状态）:
```
planning → in_progress → completed → archived
```

**新规范**（5种状态）:
```
planning → in_progress → partially_completed → completed → archived
    ↑           │              │                    │
    └───────────┴──────────────┴────────────────────┘
              (状态可回退，需记录原因)
```

**状态说明**:

| 状态 | 含义 | 进入条件 | 可执行操作 |
|------|------|----------|------------|
| `planning` | 规划中 | 计划创建 | 编辑计划内容 |
| `in_progress` | 执行中 | 开始执行第一个任务 | 更新任务状态、提交commit |
| `partially_completed` | 阶段性完成 | P0+P1任务完成 | 更新计划状态、提交阶段性报告、**不可归档** |
| `completed` | 全部完成 | 所有任务完成或用户同意 | 执行九步法步骤6-9 |
| `archived` | 已归档 | 完成步骤9 | 只读，不可修改 |

**关键改进**:
- 新增 `partially_completed` 状态，明确表示阶段性完成
- 该状态下的计划**不可归档**，防止提前归档
- 支持状态回退，需记录原因

### 2.2 归档条件（强制）

#### 归档条件1: 全部完成
```
所有任务状态 = completed
AND
所有验收标准满足
AND
代码已通过测试验证
```

#### 归档条件2: 用户明确同意
```
P0+P1任务完成
AND
用户明确同意归档未完成的计划
AND
未完成任务已迁移到新计划或标记为cancelled
AND
原计划包含完整的追溯记录（commit + 进度报告）
```

#### 归档检查清单
- [ ] P0任务全部完成
- [ ] P1任务全部完成
- [ ] P2任务全部完成（或用户同意跳过）
- [ ] P3任务全部完成（或用户同意跳过）
- [ ] 验收标准全部满足
- [ ] 有完整的Git commit记录
- [ ] 有阶段性进度报告
- [ ] 未完成任务已处理（迁移或取消）

### 2.3 进度追踪机制

#### 每次任务完成必须执行

1. **更新计划文档中的任务状态**
   - 更新任务清单表格中的状态列
   - 更新完成时间列
   - 记录commit hash

2. **更新TodoWrite中的任务状态**
   - 使用 `TaskUpdate` 工具更新状态
   - 确保状态一致性

3. **提交Git commit**
   - 使用规范的commit格式
   - 记录任务完成进度

4. **（可选）生成阶段性进度报告**
   - 使用进度报告模板
   - 记录阶段性工作摘要

#### 计划文档必须包含

**1. 任务清单表格**:
```markdown
| 任务ID | 任务名称 | 优先级 | 预计时间 | 执行状态 | 完成时间 | Commit |
|--------|----------|--------|----------|----------|----------|--------|
| T-001 | 任务描述 | P0 | 30分钟 | completed | 2026-01-27 | abc123 |
```

**2. 进度追踪区域**:
```markdown
## 执行进度

**当前状态**: in_progress
**开始时间**: 2026-01-27
**最后更新**: 2026-01-27 14:30

**任务完成情况**:
- P0: 1/1 (100%) ✅
- P1: 3/3 (100%) ✅
- P2: 2/5 (40%) ⚠️

**总体进度**: 6/12 (50%)
```

### 2.4 Commit规范（强制性）

#### Commit格式

```
chore(plan): 更新计划进度 - [计划名称]

完成工作:
- [任务ID] 任务描述 (状态: completed)
- [任务ID] 任务描述 (状态: in_progress)

变更文件:
- .claude/plans/[计划名称].md

任务完成进度: X/Y (Z%)
下一阶段: [下一阶段任务描述]
```

#### Commit示例

```
chore(plan): 更新P3阶段优化任务进度

完成工作:
- T-301 清理__pycache__ (状态: completed)
- T-302 测试覆盖率缺口分析 (状态: in_progress)

变更文件:
- .claude/plans/jolly-exploring-pinwheel.md

任务完成进度: 1/2 (50%)
下一阶段: 继续执行T-302覆盖率缺口分析
```

### 2.5 未完成任务处理机制

#### 机制1: 迁移到新计划

**适用场景**: P2/P3任务需要延期但不阻塞当前计划归档

**流程**:
1. 在原计划中标记任务状态为 `migrated`
2. 创建新计划，包含迁移的任务
3. 在新计划中引用原计划（追溯关系）
4. 用户明确同意后归档原计划

**示例**:
```markdown
# 原计划
| T-008 | 清理__pycache__ | P3 | 5分钟 | migrated | - | - |

> 注: 迁移到 [新计划](.claude/plans/feat-cleanup.md)，追溯ID: TR-2026-01-27-001

# 新计划
## 相关计划
- 前置计划: [.claude/plans/old-plan.md](.claude/plans/old-plan.md)
- 追溯ID: TR-2026-01-27-001
```

#### 机制2: 用户同意归档

**适用场景**: 低优先级任务决定不再执行

**流程**:
1. 在计划中标记任务状态为 `cancelled`
2. 记录取消原因和用户同意时间
3. 在归档报告中说明
4. 用户明确确认后归档

**示例**:
```markdown
| T-009 | 优化资源URI | P3 | 2小时 | cancelled | - | - |

> 取消原因: 当前格式已符合MCP标准，无需优化
> 用户同意: 2026-01-27
```

## 三、规范变更对照表

| 变更项 | 旧规范 | 新规范 |
|--------|--------|--------|
| 计划状态 | 4种 (planning/in_progress/completed/archived) | 5种 (+partially_completed) |
| 归档条件 | 完成步骤9即可 | 全部任务完成 OR 用户明确同意 |
| 进度追踪 | 无强制性要求 | 必须更新计划+提交commit |
| 未完成任务 | 无处理机制 | 迁移到新计划 or 标记cancelled |
| commit要求 | 无明确要求 | 强制要求，规定格式 |
| 追溯性 | 依赖Git历史 | 计划文档+Git双重追溯 |
| 计划模板 | 无 | 提供标准模板 |
| 进度报告 | 无 | 提供标准模板 |
| 迁移工具 | 无 | 提供迁移脚本 |

## 八、风险与注意事项

### 风险

1. **流程复杂度增加**: 新增状态和机制可能增加学习成本
2. **历史计划兼容性**: 旧计划可能缺少新增字段

### 缓解措施

1. 提供详细的模板和示例
2. 旧计划保持现状，新计划采用新规范
3. 逐步推广，先从新计划开始

## 九、总结

本次改进主要解决了计划管理流程中的以下问题：

1. **归档时机不明确**: 明确了归档的两个条件和检查清单
2. **进度追踪不透明**: 建立了强制性的进度追踪机制
3. **追溯困难**: 规范了commit格式和进度报告要求
4. **未完成任务处理**: 提供了迁移和取消两种机制

通过这些改进，项目计划管理将更加规范、透明和可追溯。
