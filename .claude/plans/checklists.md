# 开发规范检查清单

> **版本**: v1.0
> **更新日期**: 2026-01-26
> **用途**: 确保开发流程符合九步法规范

---

## 一、九步法执行检查清单

### 步骤0: 前置任务审核

**目的**: 确保基础环境准备就绪

**检查项**:
- [ ] 前一阶段计划已完成
- [ ] 文档已归档到 `archive/`
- [ ] 当前分支正确 (`develop` 或功能分支)
- [ ] 代码已同步 (`git status` 干净)

**常见问题**:
- ❌ 跳过审核直接开始 → 返回步骤0
- ❌ 在错误的分支工作 → 切换分支

---

### 步骤1: 制定开发计划

**目的**: 明确目标、范围和验收标准

**检查项**:
- [ ] 计划文档已创建 (`.claude/plans/feat-xxx.md`)
- [ ] 目标明确，范围清晰
- [ ] 交付物清单完整
- [ ] 技术依赖和风险已识别
- [ ] 验收标准已定义

**计划文档模板**:
```markdown
# 功能名称开发计划

**计划日期**: YYYY-MM-DD
**计划类型**: feat/fix/refactor/docs
**当前分支**: develop/feature-xxx
**预估时间**: X小时

## 一、问题诊断
## 二、修复方案
## 三、验收标准
## 四、关键文件路径
## 五、执行步骤
```

---

### 步骤2: 拆分任务清单

**目的**: 将计划拆分为可执行的小任务

**检查项**:
- [ ] 使用 `TaskCreate` 工具创建任务
- [ ] 任务数量 3-10 个（避免过多）
- [ ] 任务ID格式：`YYYYMMDD-序号`
- [ ] 优先级标注 (P0-P3)
- [ ] 依赖关系明确

**优先级定义**:
- **P0**: 阻塞性问题，立即处理
- **P1**: 高优先级，本周内完成
- **P2**: 中优先级，本月内完成
- **P3**: 低优先级，有时间时完成

---

### 步骤3: 执行开发工作

**目的**: 按优先级顺序执行任务

**检查项**:
- [ ] 按优先级顺序执行
- [ ] 每完成一项立即更新状态
- [ ] 遇到阻塞及时记录
- [ ] 保持代码提交原子性

**状态管理**:
```
pending → in_progress → completed
  ↑                           ↓
  └──── 未完成/不规范 ────────┘
```

---

### 步骤4: 测试验证

**目的**: 确保代码质量

**检查项**:
- [ ] 编写/更新测试用例
- [ ] 运行 `pytest --cov`
- [ ] 确保覆盖率 ≥95%
- [ ] 运行 `ruff check` (0错误)
- [ ] 运行 `mypy check` (0错误)

**质量标准**:
| 指标 | 要求 | 目标 |
|------|------|------|
| 测试覆盖率 | ≥80% | ≥95% |
| 代码检查 | 0错误 | 0警告 |
| 类型检查 | 0错误 | 完整注解 |

---

### 步骤5: 交叉验证

**目的**: 对照计划检查完成度

**检查项**:
- [ ] 对照计划检查完成度
- [ ] 验证所有验收标准
- [ ] 检查TODO状态一致性
- [ ] 发现问题及时回退状态

**回退机制**:
- 发现遗漏 → 回退TODO到 `in_progress`
- 补充完成 → 更新为 `completed`
- 重新验证 → 进入步骤5

---

### 步骤6: 更新文档

**目的**: 保持文档与代码同步

**检查项**:
- [ ] 更新技术文档
- [ ] 更新 `CHANGELOG.md`
- [ ] 更新任务追踪文档
- [ ] 检查交叉引用链接

**文档更新规范**:
```markdown
## [版本号] - YYYY-MM-DD

### 新增
- 功能描述

### 修复
- 问题描述

### 文档
- 文档更新说明
```

---

### 步骤7: 阶段性审计

**目的**: 内部审查，确保质量

**检查项**:
- [ ] 审查是否100%按计划执行
- [ ] 记录偏差和改进措施
- [ ] 确认代码质量检查通过
- [ ] 准备Git提交信息

**审计要点**:
- 是否真实记录问题？
- 是否所有验收标准满足？
- 是否文档已同步更新？

---

### 步骤8: Git提交

**目的**: 版本控制

**检查项**:
- [ ] 代码通过所有测试
- [ ] 代码通过质量检查
- [ ] 文档已同步更新
- [ ] 使用规范的commit信息

**Commit格式**:
```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type类型**:
- `feat`: 新功能
- `fix`: Bug修复
- `docs`: 文档更新
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建/配置

---

### 步骤9: 阶段汇报

**目的**: 总结和归档

**检查项**:
- [ ] 汇总已完成任务
- [ ] 记录问题和解决方案
- [ ] 记录测试和质量指标
- [ ] **归档计划到 `archive/`**

**归档命名规范**:
```bash
archive/YYYY-MM-DD-{type}-{original-name}.md

# 示例
archive/2026-01-26-feat-add-mcp-tool.md
archive/2026-01-26-fix-packaging-issue.md
```

## 二、Git规范检查清单

### 分支管理

**检查项**:
- [ ] 使用正确的分支前缀
  - `feature/` - 新功能
  - `fix/` - Bug修复
  - `hotfix/` - 紧急修复
  - `refactor/` - 重构
  - `docs/` - 文档更新
- [ ] 分支名称描述清晰
- [ ] 从 `develop` 分支创建
- [ ] 推送到远程

**分支操作**:
```bash
# 创建功能分支
git checkout develop
git pull origin develop
git checkout -b feature/your-feature-name
git push -u origin feature/your-feature-name
```

---

### Commit规范

**检查项**:
- [ ] 使用格式：`<type>(<scope>): <subject>`
- [ ] Type选择正确
- [ ] Scope合理指定或省略
- [ ] Subject描述简洁明确（≤50字符）
- [ ] Body包含详细说明（可选）
- [ ] Footer包含关联信息（可选）

**提交示例**:
```
feat(工具): 添加批量验证功能

实现批量验证多个Agent-Skill的功能。
- 支持并发控制，默认最多5个并发
- 使用Progress bar显示进度
- 返回详细的验证结果报告

测试: 新增8个测试用例，覆盖率95%

Closes #123
```

## 四、常见问题检查

### 问题1: 测试失败

**诊断**:
```bash
# 查看失败详情
uv run pytest -v

# 运行特定测试
uv run pytest tests/test_specific.py::test_function

# 查看覆盖率
uv run pytest --cov --cov-report=term-missing
```

**解决**:
- 修复代码使测试通过
- 或更新测试用例（如果测试不合理）
- 重新运行验证

---

### 问题2: 代码检查失败

**诊断**:
```bash
# ruff检查
uv run ruff check .

# 自动修复
uv run ruff check --fix .

# mypy检查
uv run mypy src/
```

**解决**:
- 添加类型注解
- 修复导入错误
- 调整代码结构

---

### 问题3: 计划未完成但声称完成

**预防**:
- 在步骤5交叉验证时严格检查
- 使用TODO回退机制
- 真实记录偏差

**处理**:
1. 识别未完成的任务
2. 回退TODO状态到 `in_progress`
3. 完成任务后再更新状态
4. 修正阶段报告
