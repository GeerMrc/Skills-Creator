# 交叉验证检查清单

> **版本**: v1.0
> **创建日期**: 2026-01-22
> **用途**: 确保所有开发工作符合原始计划

---

## 验证步骤

### 步骤 1: 对照原始计划检查完成度

- [ ] **确认计划文档存在**
  - [ ] 计划文档位于 `.claude/plans/` 目录
  - [ ] 计划文档使用规范命名（feat-*.md, fix-*.md, 等）
  - [ ] 计划状态标识正确（planning/in_progress/completed）

- [ ] **确认目标达成**
  - [ ] 回顾计划中的目标列表
  - [ ] 验证每个目标是否实现
  - [ ] 记录未完成目标及原因

- [ ] **确认范围符合**
  - [ ] 只实现计划范围内的工作
  - [ ] 无超出范围的金箔（gold-plating）
  - [ ] 无遗漏的核心功能

### 步骤 2: 验证所有验收标准

- [ ] **功能验收**
  - [ ] 所有声称的功能正常工作
  - [ ] 边界情况得到处理
  - [ ] 错误处理完善

- [ ] **质量验收**
  - [ ] 测试覆盖率 ≥ 95%
  - [ ] 所有测试通过（pytest）
  - [ ] 代码检查 0 错误（ruff + mypy）
  - [ ] 无安全高危问题

- [ ] **文档验收**
  - [ ] 文档与代码一致
  - [ ] 交叉引用链接有效
  - [ ] CHANGELOG 已更新

### 步骤 3: 确认无遗漏的边界情况

- [ ] **输入验证**
  - [ ] 所有公共API验证输入
  - [ ] 异常输入有适当错误消息
  - [ ] 无未捕获的异常

- [ ] **边界条件**
  - [ ] 空值、null、None 得到处理
  - [ ] 极端值（最大、最小）得到处理
  - [ ] 并发/竞态条件得到考虑

### 步骤 4: 进行代码自审

- [ ] **代码审查**
  - [ ] 代码符合项目规范
  - [ ] 变量和函数命名清晰
  - [ ] 无重复代码
  - [ ] 无硬编码常量

- [ ] **性能检查**
  - [ ] 无明显性能问题
  - [ ] 无内存泄漏
  - [ ] 无不必要的资源消耗

- [ ] **安全检查**
  - [ ] 无注入漏洞（SQL、命令、代码）
  - [ ] 无敏感信息泄露
  - [ ] 输入验证完整

### 步骤 5: 对照 CLAUDE.md 开发规范

- [ ] **七步法开发流程**
  - [x] 步骤1: 制定开发计划
  - [x] 步骤2: 拆分任务清单
  - [x] 步骤3: 执行开发工作
  - [x] 步骤4: 测试验证
  - [ ] 步骤5: 交叉验证（当前步骤）
  - [ ] 步骤6: 更新文档
  - [ ] 步骤7: 阶段性审计

- [ ] **Git 规范**
  - [ ] 使用规范命名（feature/*, fix/*, 等）
  - [ ] Commit 消息符合 Conventional Commits
  - [ ] 无直接推送到 main 分支

- [ ] **禁止行为**
  - [ ] 无虚假审核
  - [ ] 无跨流程开发
  - [ ] 无绕过测试直接提交
  - [ ] 无危险命令执行

### 步骤 6: 记录验证结果

- [ ] **验证通过项**
  - [ ] 列出所有通过的检查项
  - [ ] 记录测试结果摘要

- [ ] **验证失败项**
  - [ ] 列出所有失败的检查项
  - [ ] 记录失败原因
  - [ ] 制定修复计划

- [ ] **偏差说明**
  - [ ] 记录与原计划的偏差
  - [ ] 解释偏差原因
  - [ ] 评估偏差影响

---

## 使用说明

1. **在完成每个开发阶段后使用此清单**
2. **逐项检查并勾选已完成的项**
3. **对于未通过的项，记录原因并制定改进计划**
4. **将验证结果作为阶段性审计汇报的一部分**

---

## 验证报告模板

```markdown
### 交叉验证报告

**计划名称**: [计划名称]
**验证日期**: [日期]
**验证人**: [姓名]

**验证结果**: [通过/部分通过/未通过]

**通过项**: [列出通过的检查项]

**失败项**: [列出失败的检查项及原因]

**偏差说明**: [如有偏差，说明原因和影响]

**改进计划**: [如有失败项，说明改进计划]

**建议**: [后续改进建议]
```
